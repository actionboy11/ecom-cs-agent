# 正常退货

## 前置条件

同时满足才走本 skill：

- 订单已签收
- `tags` 不含 `custom`
- 签收次日起 7 个自然日内
- 商品完好、不影响二次销售

任一条不满足，按「分支」处理，不要硬走。

## 步骤

1. 确定订单。
   - 没有订单号：先用 `order-lookup` skill 找到唯一订单
   - 有订单号：`query_order`
   **完成条件**：拿到订单状态、`tags`、`deliveredAt`。

2. 检查 `tags`。
   **完成条件**：确认不含 `custom`；含 `custom` 立即停，改用 `custom-return`。

3. 检查签收时间。
   **完成条件**：算出签收后第几天。

4. 按分支处理：

| 情况 | 动作 |
|---|---|
| 未签收 | 说明签收后才能申请；运输中可拒收或等签收 |
| 签收 ≤7 天、非质量 | 走 P01 七天无理由 |
| 签收 ≤15 天、有质量问题 | 走 P02 质量问题退换 |
| 签收 >7 天、无质量问题 | 说明超期；可转人工 |
| 签收 >15 天 | 说明超期；转人工 |

5. 查政策：`search_policy("七天无理由退货")` 或 `search_policy("质量问题退换")`。
   **完成条件**：拿到对应条款号 P01/P02。

6. 说明关键信息：运费谁承担、寄回时效、需要保持商品完好。
   **完成条件**：用户知道下一步怎么做。

7. 调 `create_return`，等待用户确认。
   **完成条件**：出现确认卡；用户确认前不提交。

8. 用户确认后，告知售后单号和退货地址/寄回方式。
   **完成条件**：用户拿到可执行的下一步。

## 退款 vs 退货冲突

用户说「退款/退钱」，但订单已签收、按 P01/P02 需要退货时：

1. 说明「需要寄回商品才能退款」
2. 问用户是否接受退货退款
3. 用户接受 → 按退货流程走 `create_return`
4. 用户只要钱、不愿寄回 → 说明政策不允许，转人工

不要直接 `create_refund`，也不要直接 `create_return`。

## 禁止

- 未确认就 `create_return`
- 用 `create_refund` 代替退货
- 把定制商品按七天无理由提交
- 错单
- 承诺政策里没有的运费或时效

## 示例

用户：「CS2024246 这个保温杯我不喜欢了，想退。」

动作：`query_order` → 已签收、非定制、签收 3 天 → `search_policy("七天无理由退货")` → 说明 P01 → `create_return` → 等确认。
