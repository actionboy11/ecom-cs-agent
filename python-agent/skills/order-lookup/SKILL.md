# 订单定位

## 何时使用

- 用户说「我的鞋」「上周买的杯子」「昨天收到的耳机」，但没有订单号
- 用户给的订单号查不到，需要换用商品/时间重新找
- 退款、退货、换货、催件之前，订单还没确定

已有明确订单号时，直接 `query_order`，不要用本 skill。

## 输入

从用户话里提取，缺失就留空：

| 信息 | 例子 |
|---|---|
| 商品词 | 鞋、跑鞋、耳机、保温杯、行李箱 |
| 下单时间 | 昨天、上周、11月3号、最近 |
| 签收时间 | 昨天签收、11月7号收到 |
| 动作 | 退款 / 退货 / 换货 / 物流 |

相对时间先换算成绝对日期，基准是今天。

## 步骤

1. 调 `find_my_orders`，传入商品词和时间范围。
   **完成条件**：拿到候选列表。
2. 看候选的 `score` 和 `reasons`。
   **完成条件**：能判断是「唯一高分」「多个接近」还是「没有候选」。
3. 按下面分支处理。

| 情况 | 动作 |
|---|---|
| 一个候选明显高分 | 采用它，说出订单号、商品、状态 |
| 多个候选分数接近 | 列前 3 个：订单号、商品、下单/签收时间、状态；问「是哪一单」，给「都不是」 |
| 没有候选 | 列最近 3 单供核对；仍无法确定就转人工 |
| 候选属于别人 | 不查、不猜，说明只能查本人订单 |

4. 用户选定后，后续操作都锁定这一单。
   **完成条件**：只有一个订单进入下一步。

## 禁止

- 编造订单号
- 跨用户查询
- 用手机号尾号、地址等隐私信息反查
- 多个候选时直接替用户选

## 示例

用户：「上周买的跑鞋想退。」

动作：`find_my_orders(product_terms=["跑鞋"], created_from=..., created_to=...)`。

结果有两个分数接近的候选：

> 找到两笔跑鞋订单：
> 1. CS2024203，9月18日下单，已签收
> 2. CS2024205，9月20日下单，运输中
> 是哪一单？如果都不是，也可以告诉我订单号。
