# 5 分钟演示流程单

> 用途：录屏或面试现场演示。按顺序执行，每步只说一句话；翻车时看「兜底」。
> 前置：`docker compose up -d` 全部 healthy；`ollama pull bge-m3` 已就绪；`.env` 有 `JWT_SECRET`、`INTERNAL_AUDIT_TOKEN`、`DEEPSEEK_API_KEY`。

## 时间轴

| 时间 | 场景 | 在哪一栏 | 输入 | 预期 |
|---|---|---|---|---|
| 0:00–0:30 | 登录 | 左侧边栏 | `buyer_a` / `demo123` | 进入双栏，右侧提示「非坐席不可用」 |
| 0:30–1:30 | S1 查物流 | 买家栏 | `CS2024001 到哪了` | 物流状态 + 最近轨迹；超过 72h 会提示催件 |
| 1:30–2:20 | S2 发起售后 | 买家栏 | `CS2024002 尺码不合适，我要退款` | 生成售后单号，状态 PENDING |
| 2:20–3:10 | S3 政策问答 | 买家栏 | `退货政策是几天` | 回答带 `[P01]` 引用 |
| 3:10–4:10 | S4 坐席审批 | 退出 → `cs_agent` / `demo123` | 右侧选待办 → 通过（可填备注） | 列表刷新；买家再查状态变为 APPROVED |
| 4:10–4:40 | S5 越权拦截 | 换回 `buyer_a` | 买家栏输入 `查一下 CS2024005 的物流` | 统一「没有找到对应的记录」，不暴露是否存在 |
| 4:40–5:00 | 审计 | `cs_agent` 右侧 | 展开「最近审计」 | 看到 LOGIN / THREAD_ACCESS / DENIED 记录 |

## 每步口播

- **登录**：身份来自 Java JWT，买家与坐席权限不同；UI 只做编排。
- **S1**：这一步走 MCP 工具，模型只能传订单号，用户身份由服务端注入。
- **S2**：售后统一建模（退款/退货/换货一张表），状态机 PENDING → 审批。
- **S3**：Chroma 检索 + 0.35 相关性阈值，回答带 `[P01]` 引用，可核对来源。
- **S4**：审批在 Java 侧鉴权（仅 CS_AGENT），审批与查询都写审计。
- **S5**：越权统一 404 文案 + DENIED 审计，避免资源枚举。

## 兜底

| 现象 | 处理 |
|---|---|
| 回答像是模板 | 正常：模型超时会降级模板，说明「这是兜底链路，评测里单独统计」 |
| 政策回答没有 `[P0x]` | 说明检索未命中阈值，展示「没有查到」拒答而不是硬编 |
| 审批列表为空 | 先跑 S2 生成一条 PENDING；或 `docker compose restart java-service` |
| 右侧报「无法连接」 | `docker compose ps` 看 java-service/python-agent 是否 healthy |
| 越权演示返回 401 | 令牌过期（2h），重新登录 |

## 录屏清单

1. 终端：`docker compose ps` 全 healthy（3 秒）
2. 登录 + 买家对话（S1）
3. 售后申请（S2）
4. 政策引用（S3，放大 `[P01]`）
5. 坐席审批（S4，展示状态变化）
6. 越权（S5）+ 审计面板
7. 结尾：`docs/eval/` 三层评测数字一页
