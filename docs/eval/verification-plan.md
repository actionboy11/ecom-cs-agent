# 150 条 ReAct 验证计划

## 目标

用一套可复现的 held-out 评测，回答三个问题：

1. 当前 ReAct Agent 的任务完成率是多少？
2. 和规则基线、旧 workflow 比，提升多少？
3. 哪些能力仍然不可靠，是否需要用 skill 强制？

## 非目标

- 不继续加功能
- 不用 pilot 26 条当最终结论
- 不用旧 workflow 的 100 条 88% 代表当前系统

## 阶段

### Phase 0：冻结定义（0.5 天）

产出：

- 评测基准日：`2026-11-15`
- 150 条题集 schema
- judge rubric
- 基线定义：规则基线 + 旧 workflow + 新 ReAct

验收：

- 题集字段、期望类型、禁止项固定
- 任何后续改动必须升版本，不偷偷改题

### Phase 1：固定时钟（1 天）

需要冻结的时钟面：

| 位置 | 现状 | 改法 |
|---|---|---|
| Python 相对时间解析 | `datetime.now()` | 注入 `today` |
| ReAct system prompt 的当前时间 | 真实时间 | 注入 `EVAL_TODAY` |
| Java 订单 recency 打分 | `LocalDate.now()` | 读 `EVAL_TODAY`，生产为空则真实日期 |
| 退款/退货天数判断 | 真实日期 | 同一时钟 |
| 题集日期 | 固定 fixture | 与 `2026-11-15` 对齐 |

验收：

- 同一批用例在 `EVAL_TODAY=2026-11-15` 和 `2026-11-16` 下，工具参数和判定结果一致
- pilot 26 条重跑结果不变

### Phase 2：写 150 条 held-out（2 天）

组成建议：

| 类型 | 数量 |
|---|---|
| 单轮 | 120 |
| 确认脚本（2–3 步） | 30 |

单轮配额：

| 能力 | 数量 |
|---|---|
| 订单定位 | 25 |
| 物流 | 15 |
| 退款 | 20 |
| 正常退货 | 20 |
| 定制退货 | 10 |
| 换货 | 10 |
| 催件 | 10 |
| 政策问答 | 5 |
| 边界/安全 | 5 |

确认脚本配额：

| 场景 | 数量 |
|---|---|
| 退款确认 | 8 |
| 退款取消 | 4 |
| 退货确认 | 8 |
| 换货确认 | 5 |
| 澄清→选单→确认 | 5 |

要求：

- 3 个独立 writer，只拿能力契约 + fixture + schema
- 不给实现、不给已有 pilot、不给已知 bug
- 覆盖：自然表述 / 报单号 / 错别字 / 多商品 / 多动作 / 情绪 / 对抗
- 每类至少 20% hard
- 校验器检查：订单存在、归属正确、span、期望可判定、无重复

验收：

- 150/150 通过结构校验
- 题集 hash 冻结
- 写题不引用 pilot 已用订单

### Phase 3：执行器（1 天）

能力：

- 单轮：记录 reply / tool_trace / interrupt / candidates / latency
- 确认脚本：澄清 → 选单 → 确认/取消
- 每条写用例前后重置售后
- 唯一 thread
- 失败要显式记录，不吞 reset 错误

验收：

- 执行 150 条无 harness 报错
- 所有 transcript 可复盘

### Phase 4：跑 + judge（1 天）

先跑：

- 规则基线
- 旧 workflow（`REACT_ENABLED=false`）
- 新 ReAct

judge：

- 两个独立 judge，结构化输出
- 评分维度：
  - 任务完成
  - 工具/订单正确
  - 政策引用
  - 安全/确认
  - 澄清质量
  - 转人工是否合适
- 硬失败（任一即失败）：
  - 错单
  - 未确认写入
  - 泄露他人
  - 编造政策

人工校准：

- 从 150 条中分层抽 30 条
- 人工不知道 judge 结果
- 计算：
  - 总通过一致率
  - 分维度一致率
  - Cohen's kappa

门槛：

- 一致率 ≥85%
- kappa ≥0.6
- 关键安全项不能有 judge 假阴性

不达标：

- 先改 rubric/示例
- 不改 judge 阈值来“凑”一致率

### Phase 5：报告 + 决策（0.5 天）

报告：

- 总体通过率 + Wilson CI
- 分类别通过率
- 三个系统对比
- 关键失败清单
- 稳定性：30 条重复 3 次
- 成本/延迟

决策：

- skill 调用召回率 <95% → 再做 skill 强制
- 否则不急着加

## 风险

| 风险 | 处理 |
|---|---|
| judge 与人工不一致 | 先校准，不达标不出报告 |
| 题集泄漏 | writer 不看 pilot/实现；hash 冻结 |
| 相对时间漂移 | 固定时钟，两个日期回归 |
| 写操作污染 | 每例重置 + transcript |
| 模型波动 | 30 条重复 3 次，报告方差 |
| 基线不公平 | 三个系统跑同一 150 条 |
