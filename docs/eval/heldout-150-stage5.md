## 与 107/150 的关系

107/150 是 Stage 3 之前、旧“确认卡”流程下的结果。  
本次 90/150 **不能直接当作退步**，因为 v1 用例的期望大量还是：

- 退款/退货必须 `write_approval`
- 退货直接进确认卡，不填原因
- 地址/发票直接给表单

Stage 4 之后：

- 已签收退货/换货先给 `user_action` 表单
- 运输中先拦截
- 地址/发票先识别订单
- 表单提交即用户确认

所以 v1 的 `confirm` 用例会大面积失败，这是**期望过时**，不是全部是系统错误。

## 过程中修掉的回归

```python

```

- 历史订单 / 历史账单 / 全部订单 / 订单列表

修复后 **81 → 90**。
