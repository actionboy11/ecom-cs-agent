# 商品实体链接契约

> 只定义行为，不含实现。目标是让「蓝牙而机」「耳机套」这类输入有可测试的、统一的处理规则。

## 1. 目标

把用户话里的商品 mention 链接到商品目录实体：

- 错别字可以纠正
- 派生词/配件不吞掉
- 匹配不到就返回 `NIL`，不强行归到最近商品
- 一句话多个商品返回多个 mention

## 2. 非目标

- 不负责选订单
- 不负责判断退款/退货/换货
- 不负责跨用户查询

匹配结果只用于**路由**和**工具参数**，最终订单仍由 `find_my_orders` 打分。

## 3. 术语

| 术语 | 定义 |
|---|---|
| 目录实体 | 商品目录中的 `item_name`，如「蓝牙耳机」「保温杯」 |
| 别名 | 人工维护的等价说法，如「蓝牙耳机」「降噪耳机」 |
| mention | 用户话里指向某个商品的文本片段 |
| span | mention 在原文中的 0-based 起止，结束下标不包含 |
| 错别字 | 与别名同长度、同音或高字符相似的输入 |
| 派生词 | 别名前后多出实义汉字，如「耳机套」「耳机壳」 |
| NIL | 没有匹配到目录实体 |
| unknown | 识别到商品 mention，但目录中没有对应实体 |

## 4. 输入

```json
{
  "text": "蓝牙而机这个订单",
  "catalog": [
    {"canonical": "耳机", "names": ["蓝牙耳机", "降噪耳机", "耳机"]},
    {"canonical": "保温杯", "names": ["保温杯", "水杯", "杯子"]}
  ]
}
```

`catalog` 来自商品目录 + 别名表，不在本契约里硬编码具体商品。

## 5. 输出

```json
{
  "matches": [
    {
      "canonical": "耳机",
      "surface": "蓝牙而机",
      "span": [0, 4],
      "method": "typo",
      "score": 0.95
    }
  ],
  "unknown": [
    {
      "surface": "耳机套",
      "span": [0, 3],
      "reason": "noun_phrase_not_in_catalog"
    }
  ],
  "ambiguous": []
}
```

字段：

| 字段 | 含义 |
|---|---|
| `matches` | 成功链接的 mention，可多条 |
| `unknown` | 目录里没有的名词短语，不吞、不猜 |
| `ambiguous` | 多个候选分数接近，需要澄清 |
| `method` | `exact` / `typo` / `alias` |
| `score` | 0–1 |

## 6. 匹配规则

### 6.1 先切名词短语

匹配单位是名词短语，不是任意子串。

边界：

- 标点、空格
- 连词：和、与、及、或
- 语气/疑问：吗、呢、吧
- 谓词/查询词：查、退、换、买、要、多少钱、怎么、订单、物流

示例：

| 输入 | 名词短语 |
|---|---|
| 女儿的耳机 | 耳机 |
| 耳机多少钱 | 耳机 |
| 耳机和充电宝 | 耳机 / 充电宝 |
| 耳机套 | 耳机套 |
| 蓝牙而机这个订单 | 蓝牙而机 |

### 6.2 精确匹配

名词短语等于目录名或别名 → `method=exact`，`score=1.0`。

### 6.3 错别字匹配

只允许「同长度纠错」：

```text
len(名词短语) == len(别名)
且 (
    字符相似度 >= 0.75
    或 (
        拼音相同
        且字符相似度 >= 0.5
        且位置锚点：
          2 字别名：首字相同
          3 字以上：至少 2 个位置相同
    )
)
```

示例：

| 输入 | 别名 | 结果 |
|---|---|---|
| 蓝牙而机 | 蓝牙耳机 | 同长度 4，字符 3/4，拼音相同 → 命中 |
| 蓝呀耳机 | 蓝牙耳机 | 同长度 4，字符 3/4，拼音相同 → 命中 |
| 保温北 | 保温杯 | 同长度 3，字符 2/3，拼音相同 → 命中 |
| 登机相 | 登机箱 | 同长度 3，字符 2/3，拼音相同 → 命中 |
| 跑些 | 跑鞋 | 同长度 2，字符 1/2，拼音相同 → 命中 |
| 耳机套 | 耳机 | 长度 3 ≠ 2 → **不纠错** |

### 6.4 派生词处理

如果名词短语比命中的别名长，且多出的字紧贴别名：

```text
别名：耳机
名词短语：耳机套
→ 不返回耳机 match
→ 返回 unknown「耳机套」
```

这条规则不依赖「套/壳/膜/配件」列表；只要多出实义汉字，就不吞。

### 6.5 多商品

按连词/标点切分后逐个匹配，返回列表，不取第一个。

```text
耳机和充电宝
→ matches: 耳机、充电宝
```

### 6.6 NIL 与 unknown

| 情况 | 输出 |
|---|---|
| 名词短语不在目录，且不像任何别名 | `unknown` |
| 名词短语是别名 + 额外实义字 | `unknown` |
| 名词短语像别名但长度不同 | `unknown`，不纠错 |
| 多个候选分数接近 | `ambiguous` |
| 没有任何商品 mention | `matches=[]` |

## 7. 阈值

初始建议，需用测试集校准：

| 方法 | 阈值 |
|---|---|
| 精确 | 1.0 |
| 拼音相同 + 字符相似 | 字符 ≥0.5，score 0.9 |
| 字符相似 | ≥0.75，score 0.75–0.9 |
| 低于阈值 | 不匹配 |

`ambiguous`：第一名与第二名分差 <0.1。

## 8. 与路由的契约

| 匹配结果 | 路由建议 |
|---|---|
| 有 matches，且消息有查/退/换/物流词 | 允许进 ReAct |
| 只有 unknown，且消息有售后词 | 先澄清，不猜商品 |
| matches 为空，消息也无可识别商品 | 按普通分类处理 |
| ambiguous | 让用户选商品 |

**匹配结果不直接选订单。**

## 9. 验收指标

测试集：`python-agent/eval/product_match_cases.jsonl`

| 指标 | 目标 |
|---|---|
| 错别字召回 | ≥90% |
| 派生词误匹配 | 0 |
| 多商品召回 | ≥95% |
| NIL 精确率 | 100% |
| span 准确率 | ≥95% |

每次改匹配规则都跑这套用例；不靠人工看单句。

## 10. 测试集结构

每行一个 JSON：

```json
{
  "id": "pm-001",
  "type": "typo",
  "input": "蓝牙而机",
  "expected": {
    "matches": [{"canonical": "耳机", "span": [0, 4]}],
    "unknown": [],
    "ambiguous": []
  },
  "notes": "同音错别字，应纠正"
}
```

`type`：`exact` / `alias` / `typo` / `compound` / `multi` / `none` / `ambiguous`。
