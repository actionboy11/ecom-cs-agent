# 越权访问统一返回 404，而不是 403

## Status

accepted

## Context

买家只能查看自己的订单与物流。当 `buyer_a` 请求 `buyer_b` 的订单时，有两种返回方式：403（明确告知无权限）或 404（假装资源不存在）。

## Decision

统一返回 **404**，同时写一条 `DENIED` 审计记录。理由：403 会泄露「该资源存在」这一事实，攻击者可以遍历订单号枚举出有效订单；404 让越权与不存在不可区分。

## Considered Options

- **403 Forbidden**：对合法用户更友好、便于调试，但泄露资源存在性。
- **404 Not Found**：安全，代价是排障时更难判断是"不存在"还是"没权限"——由审计日志补偿。

## Consequences

- 调试时必须查审计日志才能区分两类 404。
- 前端（含 Streamlit 坐席面板）不能依赖状态码做权限提示，需要读审计结果。
- 该策略必须在 Java 与 Python 两侧一致，否则不同入口行为不一致。
