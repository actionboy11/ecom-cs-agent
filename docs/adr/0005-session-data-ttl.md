# 会话数据 30 天 TTL，审计日志不随会话删除

## Status

accepted

## Context

会话状态里会留下订单号、退款原因、用户说的地址片段等个人信息。项目要长期运行做演示和评测，数据会无限累积。另一方面，审计日志是「谁对哪个资源做了什么」的追责依据，删掉就失去意义。

## Decision

会话相关数据（LangGraph `checkpoints`/`writes`、`thread_owner`、`traces/*.jsonl`）保留 **30 天**（`SESSION_TTL_DAYS` 可配），到期**物理删除**；业务审计 `audit_logs` 保留 **365 天**，且只记录操作与结果、不记录对话正文。订单、售后请求等业务事实不自动删除。

## Considered Options

- **不设 TTL**：实现最省事，但会话表无限增长，且长期留存个人信息。
- **TTL 但软删除**：可恢复，但个人信息仍在库里，「删除」名不副实。
- **按用户主动删除**：可控，但演示项目里没人会去点。

## Consequences

- 清理是异步任务，删除后会话无法恢复——演示脚本要避免依赖 30 天前的会话。
- `audit_logs` 不含对话正文，所以「谁查了哪单」可追溯，但「他说了什么」不可追溯；需要正文时只能看未过期的 trace。
- TTL 参数化后，评测与压测环境可临时调小以便验证清理逻辑。
