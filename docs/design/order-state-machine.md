# 售后订单状态机与工作台设计

基准日：以 `EVAL_TODAY` 为准；未设置时用真实日期。  
时间窗口按自然日计算：签收当天为第 0 天。

## 1. 订单状态

| 状态 | 含义 |
|---|---|
| 待发货 | 已付款，仓库未发货 |
| 已发货 | 已出库，未进入运输 |
| 运输中 | 有物流轨迹 |
| 已签收 | 有签收时间 |
| 已取消 | 订单取消 |

## 2. 状态 × 动作矩阵

| 状态 / 签收天数 | 地址 | 退款 | 退货 | 换货 | 发票 | 催件 |
|---|---|---|---|---|---|---|
| 待发货 | ✅ | ✅ 确认后 REFUND | ❌ | ❌ | ❌ | ✅ |
| 已发货 | ❌ | 拦截成功 → 确认 → REFUND | 拦截/拒收 | 拦截/拒收 | ❌ | ✅ |
| 运输中 | ❌ | 拦截成功 → 确认 → REFUND | 拦截/拒收 | 拦截/拒收 | ❌ | ✅ |
| 已签收 0–7 天 | ❌ | 退货退款 | ✅ 无理由 | ✅ 无理由 | ✅ | ❌ |
| 已签收 8–15 天 | ❌ | 质量问题退货退款 | ✅ 质量问题 | ✅ 质量问题 | ✅ | ❌ |
| 已签收 16–30 天 | ❌ | 普通退货退款 | ✅ 原因 + 买家运费 | ✅ 原因 + 买家运费 | ✅ | ❌ |
| 已签收 >30 天 | ❌ | 解释 + 转人工 | ❌ | ❌ | 解释 + 转人工 | ❌ |
| 已取消 | ❌ | 查退款进度 / 转人工 | ❌ | ❌ | ❌ | ❌ |

### 运费

| 场景 | 运费 |
|---|---|
| 0–7 天无理由 | 买家 |
| 0–7 天质量问题 | 卖家（按 P02） |
| 8–15 天质量问题 | 卖家 |
| 16–30 天普通退货/换货 | 买家 |
| 超 30 天 | 不建单 |

### 凭证

- 8–15 天质量问题：必须上传原因 + 凭证
- 16–30 天普通退货/换货：必须填写原因，不强制凭证
- 0–7 天无理由：原因选填，不强制凭证

## 3. 资格引擎

新增 Java `OrderEligibilityService`，所有入口共用：

```java
Eligibility check(Order order, Action action, LocalDate today)
```

返回：

```json
{
  "allowed": true,
  "reason_code": "SIGNED_16_30",
  "reason": "签收 16–30 天，可退货，需原因，运费买家承担",
  "shipping_payer": "BUYER",
  "requires_return_info": true,
  "requires_evidence": false,
  "requires_intercept": false
}
```

`reason_code` 枚举：

- `PENDING_REFUND`
- `IN_TRANSIT_INTERCEPT`
- `SIGNED_0_7`
- `SIGNED_8_15`
- `SIGNED_16_30`
- `SIGNED_OVER_30`
- `CANCELLED`
- `INVOICE_OVER_30`
- `ADDRESS_NOT_PENDING`

Java API、Python Agent、前端都读同一结果，不各写一套。

## 4. 所有动作先识别订单

```text
用户消息
→ 动作识别（退款/退货/换货/地址/发票/催件）
→ 订单识别
   → 显式订单号：query_order
   → 商品/时间/状态：find_my_orders
   → 唯一高分：采用
   → 多候选：前 3 + 都不是
   → 无候选：最近订单 / 转人工
→ 资格校验
→ 通过：确认卡或 user_action 表单
→ 不通过：解释 / handoff
```

约束：

- 表单里订单号只读
- 不再出现“订单号输入框”
- 订单未识别前，不弹任何业务表单

## 5. 动作流程

### 5.1 待发货退款

```text
订单识别
→ 资格：待发货
→ 确认卡
→ 用户确认
→ REFUND
```

不出现退货地址/寄回表单。

### 5.2 运输中退款

```text
订单识别
→ 资格：运输中
→ 创建拦截
→ 拦截成功 → 确认卡 → REFUND
→ 拦截失败 → handoff
```

拦截状态：

- `INTERCEPTING`
- `INTERCEPTED`
- `FAILED`

### 5.3 已签收退货

```text
订单识别
→ 资格：0–7 / 8–15 / 16–30
→ 生成退货表单：
   - 0–7：原因选填
   - 8–15：原因 + 凭证
   - 16–30：原因，运费买家
→ 用户提交
→ 确认卡
→ RETURN
```

### 5.4 换货

同退货窗口：

- 0–7 无理由
- 8–15 质量问题 + 凭证
- 16–30 原因 + 买家运费
- >30 拒绝/转人工

表单增加“目标规格”。

### 5.5 发票

```text
订单识别
→ 已签收？
→ 签收 ≤30 天？
→ 是：发票表单（抬头/税号/邮箱），订单号只读
→ 否：解释 + 转人工入口
```

### 5.6 地址

```text
订单识别
→ 待发货？
→ 是：地址表单（收件人/手机号/新地址）
→ 否：解释
```

## 6. API 变更

### 已有

```
GET  /api/orders/page
POST /api/orders/{orderNo}/address
POST /api/orders/{orderNo}/invoice
```

### 新增

```
GET  /api/orders/{orderNo}/eligibility?action=return
POST /api/orders/{orderNo}/intercept
GET  /api/orders/{orderNo}/intercept
```

### 修改

- 地址接口：服务端再次校验待发货
- 发票接口：服务端再次校验已签收 + ≤30 天
- 售后接口：校验状态窗口、运费承担、凭证要求
- `after_sales_requests` 增加 `evidence`、`shipping_payer` 字段（或独立表）

### 拦截表

```sql
order_intercepts (
  id, order_no, user_id, status, carrier, tracking_no,
  failure_reason, created_at, updated_at
)
```

### 首页

- 6 张能力卡：查订单、退货退款、换货、改地址、开发票、催件
- 最近订单
- 待处理售后
- 演示模式步骤条

### 能力卡示例

```

```

- 订单号只读
- 按动作切换字段
- 提交后展示结果/售后单号
- 失败显示原因，不静默

### 订单列表

- 每页 10 条
- 上一页/下一页
- 筛选：月份、商品、状态
